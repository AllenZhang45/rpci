# 项目原则

本项目为 COSMIC 桌面环境开发中文五笔/拼音输入法。以下四条原则用于约束技术选型与交付标准，避免"为了原生而原生"。设计与评审中出现分歧时，以这四条为准。

## 1. 输入引擎独立于 COSMIC

- 引擎不依赖 COSMIC、iced/libcosmic 的类型，也不依赖 Wayland 事件、窗口或候选窗状态。它只负责"按键/编码进，候选/提交出"。
- 前端可替换：COSMIC Wayland 前端、Fcitx5 插件、RIME 后端、测试工具都驱动同一个引擎。
- 协议适配层保持薄。未来 input-method 协议演进时，只替换适配层，不动引擎。
- 用户词库可导出、可版本化、可迁移，避免被 COSMIC 的配置路径或前端实现绑架。
- 多个前端共享同一份词库时，必须有明确的单写者或同步策略，避免互相覆盖。
- 逻辑独立不等于独立进程。优先做库；确有跨前端共享需求，再拆成服务。

## 2. 协议兼容优先于视觉原生

- "能正确提交中文"是及格线；候选框美观是加分项。顺序不能反。
- 协议兼容不止 commit：预编辑、周围文本、光标矩形、焦点切换、密码框（content type）、删除周围文本，都属于要验证的范围。
- 候选窗走 input popup surface 协议。位置、翻转、边缘避让属于协议行为，不是皮肤；视觉可以后做，popup 的正确性不能后做。
- 不以"在 COSMIC 设置里能打字"作为验收标准。真实应用能否正常输入，以第 4 条的应用矩阵为准。

## 3. 先做好输入质量，再做智能化

- 质量四要素：选词准确、响应及时、切换可靠、词库不丢失。
- 用可度量指标代替主观感受：固定语料上的首选准确率、p99 延迟（按键到候选、候选到上屏）、崩溃/卡死率、常驻内存曲线、切换成功率、词库丢失率。
- 拼音质量高度依赖语言模型。引擎接口自己定，内核优先复用成熟实现（RIME/libpinyin），再逐步替换，避免"先写三年引擎"。
- v1 明确排除云候选、AI 联想、个性化推荐等智能化功能。默认本地、可离线、隐私优先；稳定比聪明重要。

## 4. 兼容性用应用矩阵验收，而不是用设置面板验收

- 每个版本都要在固定的应用矩阵中验证，而不是只看设置页或演示程序。
- 最小矩阵：GTK4、Qt6、Electron/VS Code、Chromium/Firefox 地址栏、LibreOffice、终端、XWayland 应用、Flatpak 应用。
- 重点场景：密码框、多行文本、光标移动、预编辑、中英切换、应用间焦点切换。
- 新增支持的应用要进入矩阵并留下回归记录。矩阵本身是交付物的一部分。

## 落地顺序（建议）

1. 协议 spike：证明在 COSMIC 上能被激活、收到按键、弹出候选、提交文本。
2. 确定引擎边界与词库格式，先以成熟引擎为后端。
3. 做候选窗与 COSMIC 集成（薄层、可选）。
4. 建立质量回归与应用矩阵；最后才考虑智能化。

## 产品定位（已定）

- 主模式：五笔 86 为主，拼音兜底；输入串先按五笔解析，超过 4 码或无五笔候选时自动按拼音解析。
- 目标用户：COSMIC/Pop!_OS 上的五笔老用户。
- 差异化：COSMIC 原生集成、五笔+拼音无缝混合；开箱即用、轻量稳定、词库可导出作为质量约束。
- 原型范围、验收标准与决策门见 [PROTOTYPE.md](PROTOTYPE.md)。
