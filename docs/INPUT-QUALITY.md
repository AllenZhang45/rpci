# 输入质量 backlog

> 状态：2026-10-23。全部为 **v0.1.4 之后**的工作；v0.1.4 仍只做稳定收口。

## 优先级

| 顺序 | 项目 | 优先级 | 为什么在这个位置 |
|---|---|---|---|
| 1 | 候选翻页与更完整的候选交互 | P1 | 影响所有输入；是后续候选排序和混输验证的基础，风险低 |
| 2 | 用户词库管理：自造词、删词、调频 | P1 | 每天都会用到；混输和自定义短语都依赖可管理的用户词典 |
| 3 | 五笔/拼音混输 | P2 | 输入质量收益高，但 RIME schema 和排序复杂，必须先 spike |
| 4 | 自定义短语/快捷输入 | P2 | 依赖用户词库和设置界面；实现比混输简单 |
| 5 | 简繁切换、全半角 | P3 | 配置完整性；不依赖混输，可独立做 |
| 6 | 标点自定义 | P3 | 当前标点已可用；属于细粒度配置 |

P1/P2/P3 是相对顺序，不是发布日期承诺。

## 1. 候选翻页与候选交互（P1）

当前：

- 数字选词、退格、Esc 已可用
- 候选只显示第一页
- 没有完整的翻页、鼠标选择和候选窗交互

目标：

- 支持上一页/下一页
- 明确页码和“第 N 页”状态
- 鼠标点击候选（如果 `input_popup_surface` 和输入法抓取允许）
- 候选数量变化后不丢当前页码
- 候选布局可选：单行、两行、自适应

### 候选布局

当前开发分支已实现：

- `PageUp` / `PageDown` 翻页
- `candidate_layout = "single" | "two-row" | "auto"`
- 默认单行，两行显式开启

原固定尺寸：

```text
POPUP_W = 520
POPUP_H = 48
```

参考的两行布局（类似搜狗，但只保留输入相关部分）：

```text
┌──────────────────────────────────────────────┐
│ rqi                         第 1/2 页       │
│ 1.搜狗输入法  2.魅力  3.挽回              ‹ › │
└──────────────────────────────────────────────┘
```

第一行：

- 预编辑文本
- 可选页码 `第 N/M 页`
- 不默认显示“打字速度”；该指标需要额外统计，且不是输入必需信息

第二行：

- 编号候选
- 页箭头 `‹ ›` 只作为页码指示
- 键盘翻页先实现；鼠标点击箭头需要 popup pointer 输入和命中测试，后做

两行布局的约束：

- 两行高度约 64 逻辑像素，接近搜狗紧凑高度
- 宽度按候选内容估算并自适应，范围 200–760 逻辑像素
- 页码右对齐；第一行左侧为预编辑，右侧为页码
- 第二行右侧显示翻页箭头 `‹ ›`
- `wl_shm` 缓冲区和 `damage_buffer` 随尺寸重建
- 光标矩形仍由 `input_popup_surface` 驱动，不改协议
- 靠近屏幕底部时需要翻转或夹紧，避免越界
- 默认保持单行；两行作为配置项，已进入 iced 设置界面
- 不复制搜狗的广告、品牌、皮肤或红色首选词样式；只借鉴信息层级

配置：

```bash
ime-settings set layout two-row
# 或编辑 ~/.config/rpci/config.toml
```

```toml
candidate_layout = "single"  # single | two-row | auto
```

验收：

- 超过一页的输入可以翻页并正确提交
- 翻页不会破坏拼音兜底/五笔状态
- 鼠标不可用时，键盘路径完整
- 切换单行/两行后候选窗不越界、不遮挡光标
- 两行布局不改变候选提交顺序
- 页箭头在未实现点击前不伪装成可点击控件

## 2. 用户词库管理（P1）

目标：

- 自造词
- 删除误加词
- 调整词频/候选顺序
- 查看当前用户词条
- 备份/恢复覆盖用户词库

实现边界：

- 优先复用 RIME 的用户词典能力，不在 Rust 引擎里另造一套词库
- 设置界面提供入口；CLI 保留
- 任何迁移都必须先走升级快照

验收：

- 新造词重启后仍存在
- 删词后不再出现
- 调频后顺序变化可观察
- 导出/导入后词库一致

## 3. 五笔/拼音混输（P2，先 spike）

### 目标语义

- 1–4 码：同时考虑五笔和拼音候选
- 五笔精确匹配始终优先
- 超过 4 码：沿用拼音路径
- 不增加“纯拼音模式”开关
- 不增加“临时拼音键”

### 实现方向

优先做 **RIME 组合 schema**：

- 新建 `wubi_pinyin` 组合 schema
- 同时挂五笔和拼音词典/translator
- 在 RIME 层做候选排序
- 不改 `zwp_input_method_v2` / `zwp_text_input_v3` / 候选窗协议

不做双引擎在 Rust 层合并，除非 schema 方案被证明不可行。

### Spike 验收

```text
wqiy   → 你
nihao  → 你好
abc    → 不误提交
四码冲突 → 五笔精确项仍在第一页
```

同时检查：

- 首屏候选数量不爆炸
- 输入延迟没有明显退化
- 用户词频不会把五笔精确候选压下去
- 关闭混输后行为与当前完全一致

### 风险

- RIME 的 speller/prism/translator 组合不直观
- 五笔码和拼音串冲突
- 候选排序需要真实语料
- 用户词频同时影响两条路径

因此先 spike，不直接进主引擎。

## 4. 自定义短语/快捷输入（P2）

目标：

- 短码展开为长文本
- 日期、邮箱、常用地址等快捷文本
- 可在设置界面维护

边界：

- 不引入云同步
- 不引入账号
- 数据存本地 XDG 目录

验收：

- 新增短语后立即或重启后生效
- 删除/修改短语不会破坏用户词库
- 备份/恢复包含短语

## 5. 简繁切换、全半角（P3）

目标：

- 简体/繁体切换
- 中文全角/半角标点切换
- 状态在 applet 或设置中可见

实现边界：

- 优先通过 RIME 配置/过滤器实现
- 不改变候选窗协议
- 不引入新的顶层模式

验收：

- 切换后新提交文本正确
- 不破坏中英切换
- 重启后设置保留

## 6. 标点自定义（P3）

目标：

- 用户可改中文标点映射
- 可恢复默认
- 不要求重启整个输入法

验收：

- `.` `,` `?` 等映射可配置
- 配置错误时回退默认
- 备份/恢复包含配置

## 明确不做

- 纯拼音模式
- 云输入、账号同步、AI 联想
- 皮肤市场
- 五笔 98（除非出现真实需求）
- Windows/macOS
- 与搜狗五笔 100% 行为一致
